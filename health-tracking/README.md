# 社區智慧健康站：分層管理與閉環追蹤後台

依《彰基社區智慧健康站量測異常分層管理與閉環追蹤建議 v1》實作的後台原型。九合一設備的量測資料傳入後，系統會：

1. **自動分層**：血壓、脈搏與心律、血氧、體溫、血糖、血脂、代謝症候群、BMI／腰圍／體脂，八個項目各自判定紅、橙、黃、綠。
   - 民眾的整體層級取其中最高者。
   - **BMI／腰圍／體脂屬於生活型態追蹤**：照常判定層級並開健康處方，但不計入整體層級、不派案、不轉介。
   - 代謝症候群維持原流程：計入整體層級、派案，橙層轉介就醫。
   - **血壓採院內修訂版（2026/11）**：

     | 層級 | 閾值 |
     |---|---|
     | 綠 | 收縮壓 <140 且舒張壓 <90 |
     | 黃 | 收縮壓 140–159 或舒張壓 90–99 |
     | 橙 | 收縮壓 160–179 或舒張壓 100–109 |
     | 紅 | 收縮壓 ≥180 或舒張壓 ≥110 |
   - **血壓、脈搏、血氧以 7 天平均判定**（院內決議 2026/11）：
     - 黃、橙層取 7 天內至少 2 個場次（相隔超過 60 分鐘）的平均。7 天內只量 1 次者標「暫定」，先不開案。
     - 工作清單另列「暫定・待 7 天內再量」，請民眾 7 天內再量 1 次；7 天內未再量測，則到期以該次量測自動開案（偵測日仍是量測日，期限從開案日起算）。
     - 單次即判定、不平均的情況：紅層（≥180/110、脈搏 <40 或 >120、血氧 ≤90）、有警示症狀、心律 ARR 旗標、現場已重測 3 次的血氧。
     - 代謝症候群的血壓條件同樣用 7 天平均；層級只取決於 1 次血壓時，也是暫定。
     - 依據：個人內收縮壓變異 SD 約 11 mmHg，2 次平均約降到 7.8 mmHg；本站實際資料中，單次橙層血壓有 47% 下一次量測未再達橙層。
2. **自動開案並計算期限**：紅層當日處理、24 小時內確認就醫、就醫後 2 週電訪；橙層 4 週內就醫、3 個月複測；黃層 3 個月內完成處方、6 個月複測。
3. **追蹤流程（四步驟反覆）**：偵測 → 通知 → 介入（必附健康處方）→ 確認（就醫或完成處方）。每一步都有期限，逾期會標紅。
4. **下一輪自動開始**：
   - 確認後設定複測日：黃層 6 個月、橙層 3 個月、紅層就醫後 2 週。
   - 量測高於本輪層級：立即開始下一輪。
   - 複測日後回站仍異常：開始下一輪，層級取最近 2 次量測的較高者，所以連續 2 次較低才降級。
   - 連續 2 次綠層：回到例行量測。
   - 複測日前、沒有升高的量測：只記錄，不開新輪。
   - 複測日已過未回站：列入「待回站複測」。
   - 結案原因限：已轉由醫師持續管理（需登記回診日期）、死亡、遷出、失聯、拒絕。
   - **系統自動結案**：還在「偵測」、尚未通知、非紅層，且只因血壓、脈搏或血氧異常的輪次，之後連續 2 個場次全部正常，且目前的 7 天平均也正常，系統會自動結案（原因：後續量測連續 2 次正常），並寫入處理紀錄。已通知、紅層、或含血糖等其他項目的輪次不會自動結案。
   - 個案頁與工作清單會列出**偵測後量測**：次數、最近數值與小趨勢線，護理師打電話前就能看到民眾後來量的結果。
5. **品質指標**：紅層當日處理率、橙層就醫確認率、複測完成率、降級（達標）率、未閉環個案數與原因。附 Wilson 95% 信賴區間，可依據點拆分並匯出 CSV。

6. **健康888**：只看三高，計算找得出、要介入、有改善三項指標，附 95% 信賴區間與距目標人數，並列出各缺口的個案名單。

## 舊資料轉換

- 舊版七步驟流程的資料（待派案、已複測、判定）在開啟時會自動轉成四步驟，每案的處理紀錄都會註記。

## 規則更新時

- 分層規則有版本號（`engine.js` 的 `RULES_VERSION`）。
- **示範資料**：開啟時發現版本不同，會自動依新規則重新產生。
- **正式資料**：畫面上方會提示，按「依新規則重新判定」即可處理開放中的追蹤案：
  - 只重新評估「決定本輪層級的量測」（開輪或升級時；複測開輪則為最近 2 次），不用最近一次量測，以免繞過「連續 2 次才降級」。
  - 每案的變動都寫入處理紀錄；新規則下未達異常者，以系統原因結案，不列入品質指標的達標分子。
  - 2026-11-07 版（7 天平均）：開案量測也改用 7 天平均重新判定；已開案的單次量測照樣成立，不會因此結案。尚未有人處理、之後已連續 2 次正常的輪次會自動結案。

## 據點與負責護理師

- 在「分層規則與設定 → 據點與負責護理師」上傳年度名單（Excel，含「社區／據點」與「負責護理師」欄位，例如 2027 年社區負責護理師）。先預覽，確認後才套用。
- 套用後：
  - 新偵測的追蹤案**自動派給該據點的負責護理師**。
  - 可選擇把進行中的案件改派給新負責人，每案都寫入處理紀錄。
  - 院內主機版會一併把姓名相符的護理師帳號，可見據點更新為其負責的據點。
- 名冊上的據點寫法會統一成年度名單的名稱，例如「秀水頭前」→「頭前社區」、「金齡關懷協會-1～86」→「永福教會松年團契」。匯入時自動套用；既有資料可按「統一名稱」。
- 預覽會列出：未指定負責人的據點（例如名單寫「新工」）、有民眾但不在新名單上的據點，以及每位護理師的負擔（據點數、民眾數、進行中案件）。

## 健康處方內容

- 內容來自院內《健康處方》文件，轉錄在 `rx-library.js`。
- 依**量測數值**選擇文件中的類別，例如 LDL 160–189 為「LDL高風險」。
- 血壓例外：依院內修訂版分層選擇，不用文件原本的 120/80、130/80 閾值。黃、橙、紅層都用「高血壓警示」；黃層不轉介，所以不印文件裡的就醫建議。
- 再依紅橙黃綠層級附上追蹤計畫（就醫時限、複測），最後附三條警語。
- 文件未涵蓋的數值範圍，會標註「院內衛教文件未涵蓋」，改用系統暫用文字。
- 護理師開立前都可以修改。

## 健康888 指標定義（只看三高：血壓、血糖、血脂）

| 指標 | 分母 | 分子 |
|---|---|---|
| 找得出 | 健康站已建立個資的民眾 | 健康站量測三高至少 1 次 |
| 要介入 | 三高至少一次進入黃層以上的民眾 | 進入管理流程 |
| 有改善 | 三高至少一次進入橙層以上的民眾 | 曾經降級過 |

- **三高層級**：每個量測場次取血壓、血糖、血脂三項中最高的層級。脈搏、血氧、體溫、體位、代謝症候群不納入。
- **血壓用 7 天平均**：與分層規則一致。7 天內有再量的單次量測，併入下一次的平均，不單獨計算；7 天內沒有再量的單次量測，以該次計。
- **進入管理流程**：該民眾含三高異常項目的追蹤案，在觀察期內到達「已通知」。可在設定頁改成「已介入」或「已確認」。
- **曾經降級過**：首次達橙層以上之後，三高層級連續 2 個場次低於先前的最高層級。
  - 可在設定頁改成「任 1 個場次」。
  - 之後若再升高，最高層級會跟著提高，需要再降級一次才算。
  - 預設要求連續 2 次，是為了減少測量誤差與趨中迴歸造成的假性改善，也和文件「連續 2 次才降級」的規則一致。
- **至少一次進入某層**：觀察期內任一場次的三高層級達到該層以上。同一場次重測後回到綠層者不計。
- 觀察期預設 365 天，目標 80%，都可在設定頁調整。
- 總覽頁的「總篩檢人數」計入任何量測項目，不限三高、不限期間。

## 使用方式

直接用瀏覽器開啟 `index.html`（雙擊即可，不需伺服器）。第一次開啟會載入**虛構示範資料**：約 170 位合成民眾、9 個月的量測與處理紀錄，可直接操作。

| 頁面 | 用途 |
|---|---|
| 總覽 | 總篩檢人數、各層級人數與逾期數、需優先處理清單、各據點層級分布、流程停留階段、品質指標摘要 |
| 追蹤工作清單 | 護理師每日工作：依逾期、層級、期限排序；可篩選層級、階段、只看逾期、只看派給我 |
| 民眾名冊 | 每人的管理層級與最近一次量測的 8 項層級 |
| 個案頁 | 逐項判定依據、四步驟操作表單、健康處方（自動產生、可修改、可列印）、趨勢圖、歷次追蹤 |
| 品質指標 | 5 項指標的定義、分子／分母、95% 信賴區間，各據點比較 |
| 健康888 | 三高的找得出／要介入／有改善三項指標、缺口名單 |
| 資料匯入 | 名冊 Excel（優活雲格式）、量測 CSV／Excel、備份與還原 |
| 分層規則與設定 | 規則對照表、系統解讀清單、處理時限設定、社區護理師名單 |

### 名冊匯入

可以直接上傳各據點填寫的「優活雲批次建立個案名單」Excel，每個工作表是一個據點。系統會自動處理目前名冊常見的格式問題：

- 民國年（`40.07.20`、`40,10,20`）轉為西元
- 年份重複加了 1911（例如 3858 年），自動校正
- 身高用公尺填寫（例如 1.54），轉為公分
- 身分證號填在「身份識別類型」欄，自動找到
- 驗證身分證號檢查碼、性別與證號第 2 碼是否一致
- 以身分證號去除重複

無法自動判斷的資料（例如 `0934-10-21`、檢查碼錯誤）會列入「需確認清單」，可下載成 CSV 交給據點修正。

### 定期匯入量測

- **整份匯入即可，不用挑新資料。** 系統以「同一位民眾＋同一個量測時間」比對，已匯入過的自動略過，只加入新的；匯出的日期區間重疊也沒關係。
- 選檔後先預覽：會顯示「其中 N 筆先前已匯入過，只匯入新的 M 筆」；整份都匯入過則提示不需再匯入。
- **期限從匯入日起算**：匯入的量測，處理期限從匯入當天開始計算；偵測日仍顯示實際量測日。工作清單上，若有歷史匯入造成、尚未有人處理的逾期案件，可按「期限從今天重新起算」（只影響仍在「偵測」的案件，並寫入處理紀錄）。
- 已匯入的量測若之後在設備端被修正（同一時間、不同數值），不會覆蓋舊值；需要更正時請在個案頁手動處理。

### 量測匯入欄位

`識別值, 量測時間, 收縮壓, 舒張壓, 脈搏, 心律旗標, 血氧, 體溫, 血糖, 血糖類型, LDL, 三酸甘油脂, HDL, 總膽固醇, 尿酸, 體重, 腰圍, 體脂率, 症狀`

- 頁面上可以下載範本。
- 同一人 60 分鐘內的多筆量測視為同一場次的重測，合併判定。例如血氧 91–94，需再重測 2 次仍低才升為橙層。

## 需臨床委員會確認的規則解讀

文件中有幾處不一致或未定義的地方。系統的處理方式都列在「分層規則與設定 → 系統解讀」，重點如下：

- **血壓合併症狀**：院內修訂版刪除了原本「≥160/100 合併胸痛、劇烈頭痛、言語不清、肢體無力即列紅」。系統把這種情況列為橙層，同時標示「急」，提示立即評估。
- **未定義的情況**：無症狀低血糖（<70）、有症狀的脈搏 50–59，文件都沒有定義，系統暫列為橙層。
- **派案時限**：文件未訂「派案／通知」的時限。系統預設紅 0 日、橙 3 日、黃 14 日，可在設定頁調整。

## 資訊安全

### 已做到（皆有自動化測試驗證）

| 威脅 | 防護 |
|---|---|
| 電腦被他人使用、瀏覽器資料外流 | 正式資料一律以 **AES-256-GCM** 加密後才存入瀏覽器；金鑰由通行密語經 **PBKDF2-SHA256 600,000 次**衍生（OWASP 2023 建議值）、不可匯出、只在記憶體 |
| 離開座位忘記登出 | 閒置 15 分鐘自動鎖定；可手動鎖定；鎖定後畫面不留任何個資 |
| 猜測通行密語 | 通行密語至少 12 字；連續 3 次錯誤後指數延遲（最長 15 分鐘） |
| 備份檔外流或被竄改 | 備份一律加密匯出；GCM 驗證，竄改即無法開啟 |
| 竄改的備份檔注入惡意內容 | 還原前嚴格驗證欄位、ID 格式與列舉值，不符即拒絕 |
| 跨站腳本（XSS） | 所有資料輸出皆跳脫；另加 **Content-Security-Policy**：只允許本機腳本、禁止內嵌腳本與任何對外連線 |
| 第三方程式庫漏洞、CDN 供應鏈攻擊 | 移除 SheetJS 0.18.5（CVE-2023-30533、CVE-2024-22363），改用自製讀取器；**零外部相依、零對外連線** |
| 惡意 Excel（壓縮炸彈、原型污染、XXE） | 解壓大小上限並邊讀邊計數；以 Map 存放檔案內容；以瀏覽器 DOMParser 解析（不載入外部實體） |
| CSV 公式注入 | 匯出時 `= + - @` 開頭的文字前加 `'` |
| 輸入或設備錯誤 | 量測值超出生理合理範圍即拒收 |
| 操作不可追溯 | 稽核紀錄：解鎖、鎖定、設定／變更密語、查看完整身分證號、匯入、匯出、還原、清除、重新判定、結案 |
| 公開 repo 洩漏個資 | `.gitignore` 排除 xlsx、csv、json、zip；已掃描完整 git 歷史，無真實身分證號或電話 |

### 單機版的限制，以及院內主機版如何解決

單機版是一個網頁檔，資料存在各自的瀏覽器裡。以下項目單機版做不到，**院內主機版（`server/`）已經做到**：

| 項目 | 單機版 | 院內主機版 |
|---|---|---|
| 多人同時使用同一份資料 | 每台電腦各一份 | ✓ 資料集中在主機，換頁即取最新資料 |
| 身分驗證 | 「操作者」自選 | ✓ 帳號密碼登入（scrypt）、首次登入強制改密碼、失敗鎖定 |
| 依據點分權 | 無 | ✓ 護理師只看得到自己負責據點的民眾 |
| 個資最小化 | 身分證號遮蔽 | ✓ 伺服器端遮蔽，調閱完整號碼另外留紀錄 |
| 不可竄改的稽核 | 知道密語的人可修改 | ✓ 伺服器端只增不改、SHA-256 雜湊鏈、可驗證 |
| 備份 | 手動匯出 | ✓ 每日自動加密備份 |

部署方式見 **`server/DEPLOY.md`**。仍需院方處理的：院內 AD／SSO 與多因子驗證整合、納入院內備份與日誌系統、第三方弱點掃描與滲透測試，以及依個資法、醫療機構資通安全規範、院內 ISMS（ISO 27001）完成風險評鑑。

## 正式上線前必須處理

1. **部署院內主機版**：依 `server/DEPLOY.md` 由資訊室安裝（只需 Node.js，零第三方套件），放在院內 HTTPS 反向代理之後。
2. **設備資料串接**：目前以檔案匯入量測。正式上線建議由九合一 App 後端直接呼叫 API 推送量測，紅層即時通知社區護理師（簡訊或 App 推播）。
3. **設備資料對應**：確認九合一設備實際輸出的欄位與單位。例如是否提供 LDL／TG／HDL、血糖是否標註空腹或飯後；若只有總膽固醇，血脂無法依文件分層。
4. **規則版本控管**：已有規則版本號與重新判定機制；正式上線後，規則異動請經臨床委員會核定並保留紀錄。
